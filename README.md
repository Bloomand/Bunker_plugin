# Bunker

Paper-плагин для многопользовательской игры «Бункер». Игроки получают случайные характеристики, обсуждают полезность участников и голосуют за выбывание.

Каждая игра является отдельной комнатой. Несколько игр могут идти одновременно на одном сервере.

Плагин рассчитан на игроков, которые раньше не играли в «Бункер»: команды,
меню, сообщения перед этапами, текущий ход, таймер и доступные действия
объясняются прямо в игре. Основные игровые данные настраиваются через
`config.yml`, тексты — через `messages.yml`, а характеристики и катастрофы
хранятся в JSON-файлах.

## Возможности

- отдельные игровые комнаты на разных аренах;
- создание игры через команду или GUI;
- подключение через команду, GUI или случайный выбор лобби;
- каталог арен `/bunker arenas` с иконками, описаниями и статусами;
- отдельное GUI для создания игры и отдельное GUI для подключения;
- запрет создания новых игр через `game.creation-enabled` и `/bunker reload`;
- проверка занятости арены до создания игры и при клике в меню;
- строгая проверка ID арен: маленькие английские буквы, цифры, `_` и `-`;
- настраиваемые минимальное/максимальное число игроков и число победителей;
- настраиваемые таймеры всех этапов;
- личные карты игроков с категориями, названиями и описаниями;
- меню выбора характеристики и меню голосования;
- очередность личных ходов и автоматическое раскрытие карты по таймеру;
- обычное и повторное голосование при ничьей;
- ограниченные пропуски голосования;
- добровольный выход через `/bunker leave`, `/spawn` и отключение;
- автоматическая передача ведущего;
- блокировка внешних команд во время игры с whitelist команд арены;
- сохранение игр и восстановление после рестарта;
- сохранение уже раскрытых характеристик и текущего игрока после рестарта;
- все сообщения, подсказки, названия меню и правила в `messages.yml`;
- совместимость клиентов разных Java-версий через ViaVersion/ViaBackwards.

## Правила

- В игре участвует от `min-players` до `max-players` из `config.yml`.
- Создавший комнату игрок становится ведущим и участником.
- Побеждает количество игроков, заданное параметром `winners-count`.
- В каждом раунде живые игроки по очереди раскрывают по одной характеристике.
- После общего обсуждения проходит голосование за выбывание.
- Выбывший игрок больше не ходит и не голосует, но его карты показываются в финале.

## Таймеры

| Этап | Параметр |
|---|---|
| Ожидание лобби | `lobby-seconds` |
| Изучение карт | `study-seconds` |
| Ход одного игрока | `speech-seconds` |
| Общее обсуждение | `open-discussion-seconds` |
| Обычное голосование | `voting-seconds` |
| Повторное голосование | `voting-seconds` |

Оставшееся время показывается живым участникам в action bar. В чат отправляются сообщения о начале этапов, текущем выступающем и результатах.

## Быстрый сценарий

1. Ведущий использует `/bunker create`.
2. Ведущий выбирает свободную арену в меню или через `/bunker create <ID арены>`.
3. Остальные игроки открывают `/bunker games` и выбирают активную арену либо используют `/bunker join <ID арены>`.
4. После набора `min-players` человек ведущий вводит `/bunker start`.
5. Игроки изучают свои карты время `study-seconds`.
6. В чат отправляется случайное описание катастрофы.
7. Каждый живой игрок получает ход на время `speech-seconds`.
8. После всех ходов идёт общее обсуждение на время `open-discussion-seconds`.
9. Игроки голосуют за выбывание.
10. Раунды повторяются, пока не останется `winners-count` живых игроков.

## Команды

Все команды доступны через permission `bunker.use`.

### Лобби

#### `/bunker create`

Создаёт комнату. Создавший игрок становится ведущим. Игрок не может создать игру, если уже состоит в другой.

#### `/bunker games`

Показывает открытые лобби и количество игроков в каждом.

Для игроков команда открывает GUI активных лобби с иконками арен. В меню
показываются ведущий, количество ожидающих игроков и доступность комнаты.

#### `/bunker arenas`

Открывает общий каталог всех настроенных арен. Иконка, название, описание и
статус арены доступны всем игрокам. Это информационное меню: его иконки не
создают игру и не подключают игрока.

#### `/bunker rules`

Показывает полный краткий справочник для игроков, которые впервые играют в «Бункер»: цель, этапы, команды, голосование, пропуски, выход и возможности ведущего. Текст команды настраивается построчно в `messages.yml` и перечитывается через `/bunker reload`.

#### `/bunker join <ID арены>`

Подключает игрока к активному лобби выбранной арены. Подключение невозможно, если на арене нет набора, лобби заполнено или игрок уже состоит в другой игре.

Команда `/bunker games` открывает меню только с аренами, где ведущий уже создал набор, но ещё не запустил игру. В подсказке арены отображаются количество игроков, ведущий и список ожидающих участников.

Можно присоединиться к случайному открытому лобби:

```text
/bunker join random
```

Если выполнить `/bunker join` без ID, откроется GUI выбора активной игры.

#### `/bunker start`

Запускает игру. Только ведущий может выполнить команду. Нужно не меньше
`min-players` участников и корректный файл характеристик.

#### `/bunker cancel`

Отменяет игру на любом этапе. Только ведущий может выполнить команду. Победители при отмене не определяются.

#### `/bunker leave`

Выход из игры:

- в лобби игрок просто удаляется;
- если из лобби выходит ведущий, комната отменяется;
- после запуска игрок считается выбывшим;
- при двух или меньшем количестве живых игра завершается.

#### `/bunker status`

Показывает ID игры, текущий этап, общее количество участников и количество живых игроков.

### Карты и меню

#### `/bunker cards`

Показывает игроку его карты и описания. Сообщение видит только он.

#### `/bunker players`

Открывает меню участников. В нём видны номер, имя, статус жив/выбыл и уже раскрытые карты. Нераскрытые карты других игроков скрыты.

#### `/bunker open`

Открывает доступное меню заново:

- выбор характеристики во время собственного хода;
- голосование, если игрок ещё не голосовал.

Закрытие меню через кнопку выхода не засчитывает выбор. После этого меню можно открыть командой `/bunker open`.

### Ход

#### `/bunker pass`

- Игрок во время своего хода передаёт слово следующему.
- Ведущий после `host-skip-delay-seconds` может завершить изучение карт.
- Ведущий после `host-skip-delay-seconds` может завершить общее обсуждение.
- Другие игроки не могут завершить чужой ход.

Если игрок завершил ход без выбора карты, раскрывается первая нераскрытая характеристика.

#### `/bunker stopall`

Команда администратора с permission `bunker.admin`. Немедленно отменяет все лобби и активные игры без определения победителей.

Если живой игрок во время игры использует `/spawn`, он считается добровольно выбывшим. Его голос и ход больше недоступны, а остальные участники получают сообщение о выбытии.

### Голосование

#### `/bunker vote <номер>`

Голосует за игрока с указанным номером:

```text
/bunker vote 4
```

Голос можно отдать также через меню `/bunker open`.

#### `/bunker vote skip`

Выбирает пропуск голосования. За всю игру доступно два пропуска.

Если половина или больше живых участников выбрали `skip` или не проголосовали, а голосов за игроков недостаточно, голосование пропускается и расходуется один пропуск.

Если оба пропуска уже использованы и никто не получил голосов за выбывание, случайный живой игрок выбывает. Об этом сообщается в чат.

При ничьей запускается повторное голосование только между участниками с максимальным количеством голосов. В повторном голосовании `skip` недоступен.

## Этапы игры

### Лобби

Нужно собрать от `min-players` до `max-players` человек. Лобби автоматически
отменяется через `lobby-seconds` после создания, если ведущий не запустил игру.

Номера выдаются свободными последовательными значениями от 1 до 12. Внутри одной игры номера не повторяются. После выхода из лобби номер может быть выдан новому игроку.

### Изучение карт

После запуска каждый игрок получает по одной случайной карте из каждой категории. Карты можно посмотреть через `/bunker cards`.

В течение 2 минут карты видит только владелец. Одновременно объявляется случайная катастрофа из `catastrophes.json`.

### Личный ход

Живые игроки выступают по очереди:

1. открывается меню с иконками нераскрытых категорий;
2. игрок выбирает одну характеристику;
3. название характеристики показывается всем в чате;
4. игрок рассказывает о себе;
5. через `speech-seconds` ход переходит дальше.

В общий чат отправляется только категория и название характеристики, без описания. Полное описание остаётся доступно владельцу через `/bunker cards`.

Таймер длится ровно `speech-seconds` от начала хода независимо от скорости
выбора карты. Если игрок не сделал выбор, автоматически раскрывается первая
нераскрытая карта.

### Общее обсуждение

После ходов всех живых игроков начинается обсуждение на
`open-discussion-seconds`. Участники обсуждают раскрытые карты и выбирают,
кого исключить.

Ведущий может завершить обсуждение после `host-skip-delay-seconds` командой
`/bunker pass`.

### Голосование

Голосование длится `voting-seconds`. Каждый живой игрок может выбрать участника
или `skip`.

Не проголосовавшие учитываются как пропустившие голосование при проверке условия пропуска. Голосование также завершается сразу после голосов всех живых участников.

Если несколько игроков набрали одинаковое максимальное количество голосов, начинается повторное голосование между ними. В нём нельзя использовать `skip`.

## Победа и выход

Когда остаётся `winners-count` живых игроков, они объявляются победителями.
Если из-за выходов живых игроков стало меньше этого значения, игра всё равно
завершается и победителями становятся оставшиеся игроки.

В финал отправляются:

- номера и имена победителей;
- полные карты всех участников;
- карты выбывших игроков;
- названия и значения характеристик.

Итоговый отчёт получают только участники этой комнаты.

Команда `/bunker leave`, `/spawn` и отключение от сервера после начала игры считаются добровольным выбыванием. Если выбывает ведущий, роль автоматически передаётся следующему живому игроку по порядку номеров, о чём получают сообщение все участники.

## Данные игры

Плагин хранит состояние активных комнат в `plugins/Bunker/games.yml`.
Сохраняются арена, ведущий, участники, номера, карты, раскрытые категории,
живые игроки, текущая фаза, раунд, катастрофа, пропуски и текущий игрок.
Резервная копия создаётся в `games.yml.bak`. Повреждённая отдельная комната
пропускается без падения всего сервера.

## Настройка и сообщения

Игровые параметры находятся в `config.yml` и применяются при запуске или после `/bunker reload`:

```yaml
game:
  creation-enabled: true
  min-players: 3
  max-players: 12
  winners-count: 1
  lobby-seconds: 600
  study-seconds: 120
  speech-seconds: 180
  open-discussion-seconds: 120
  voting-seconds: 60
  host-skip-delay-seconds: 30
  skip-count: 2
  restore-host-wait-seconds: 180
  restore-continue-wait-seconds: 600
```

Параметр `game.creation-enabled` управляет созданием новых игр. Если установить его в `false`, новые комнаты нельзя будет создать ни командой `/bunker create`, ни через меню выбора арены. Значение применяется после `/bunker reload`; уже созданные игры продолжаются.

Арены хранятся в `config.yml` в разделе `arenas`. Каждая арена имеет уникальный ID, название, описание, иконку, обязательную точку `start` и разрешённые команды:

```yaml
arenas:
  bunker:
    name: "Главный бункер"
    description: "Основная арена для игры"
    icon: CHEST
    start:
      world: bunker_world
      x: 100.5
      y: 65
      z: -20.5
      yaw: 90
      pitch: 0
    allowed-commands:
      - spawn
```

На одной арене может быть только одна активная игра. Ведущий выбирает свободную арену через меню после `/bunker create`. Игроки открывают `/bunker games`, выбирают активную арену и подключаются к её лобби. Меню поддерживает страницы и случайный выбор только доступной комнаты. Также доступны команды `/bunker create <ID арены>` и `/bunker join <ID арены>`.

Для установки точек внутри игры используйте команды администратора:

```text
/bunker setarena <ID арены> start
```

Команда сохраняет текущую позицию, мир и направление взгляда в `config.yml`. Пока идёт набор, игроки не телепортируются и могут заниматься своими делами. Только после `/bunker start` участники телепортируются на `start` с небольшим случайным смещением. После завершения игры они остаются на территории бункера и выходят с неё через `/spawn`. Во время активной игры внешние команды, кроме перечисленных в `allowed-commands`, блокируются; внутренние команды `/bunker` остаются доступны. Команда `/spawn` считается добровольным выходом из игры.

Если указанного ID арены ещё нет, команда создаёт её сразу вместе с текущей точкой старта, стандартной иконкой `CHEST`, пустым описанием и разрешённой командой `/spawn`. Арены без корректной точки `start` не отображаются и не могут использоваться. Точку можно только переставить этой командой либо удалить всю арену.

Удаление арены:

```text
/bunker deletearena <ID арены>
```

Удалить арену с активной игрой нельзя. Алиас команды: `/bunker delarena <ID арены>`.

Все основные сообщения находятся в `messages.yml`. В нём можно менять цвета, формулировки и подсказки. Для подстановок используются переменные вида `%player%`, `%id%`, `%seconds%` и другие, указанные в исходном тексте сообщения.

Команда `/bunker reload` доступна игрокам с permission `bunker.admin` и перечитывает `config.yml`, `messages.yml` и игровые JSON без перезапуска сервера. Уже запущенные таймеры не пересоздаются; новые значения применяются к следующим этапам и играм.

## Перезапуск сервера

Состояние активных комнат автоматически сохраняется примерно раз в 30 секунд, после важных изменений и при выключении сервера в `plugins/Bunker/games.yml`. Предыдущая версия хранится в `games.yml.bak`. Сохраняются участники, ведущий, номера, карты, раскрытые характеристики, живые игроки, катастрофа, раунд и текущий этап.

После запуска сервер восстанавливает комнаты в режиме ожидания возвращения. Сначала игра ждёт ведущего время `restore-host-wait-seconds` (по умолчанию 3 минуты). Если ведущий не вернулся, игра завершается.

После возвращения ведущего запускается второе окно `restore-continue-wait-seconds` (по умолчанию 10 минут). Ведущий получает предложение выполнить `/bunker continue`. Команда фиксирует состав из вернувшихся игроков и продолжает игру с сохранённого этапа. Игроки, которые не успели вернуться к этому моменту, исключаются из состава и считаются пропавшими без вести; позже они уже не добавляются. Если вернувшихся живых игроков не больше `winners-count`, игра завершается.

Если ведущий не выполнит `/bunker continue` за второе окно ожидания, игра удаляется. Пока ведущий не вернулся, подключившиеся участники только отмечаются как вернувшиеся и ждут решения ведущего.

После подтверждения этап начинается с полным таймером из текущего конфига. Текущие голоса сбрасываются, но уже раскрытые характеристики сохраняются. Во время личного хода сохраняется текущий игрок в очереди и факт раскрытия его карты: после рестарта он продолжает свой ход, а вторая карта автоматически не раскрывается.

Для безопасного обновления используйте `stop`, а затем запустите сервер снова:

```text
stop
java -Xms1G -Xmx2G -jar paper.jar --nogui
```

```text
├── catastrophes.json       # Варианты катастроф
└── plugin.yml              # Метаданные, команда и permissions
```

### Запуск и выключение

`BunkerPlugin.onEnable()` выполняет операции в следующем порядке:

1. создаёт `ConfigManager` и загружает конфигурацию;
2. создаёт `GameManager`, который читает игровые параметры и арены;
3. регистрирует `/bunker` через `Commands`;
4. регистрирует `GameManager` как Bukkit listener;
5. восстанавливает комнаты из `games.yml`.

При выключении `GameManager.shutdown()` отменяет свои задачи, синхронно сохраняет комнаты и затем отменяет таймеры игр. Bukkit также автоматически отменяет задачи плагина при полном выключении сервера.

### Основные модели и состояние

`GameManager` хранит:

- `arenas` — настроенные арены по нормализованному ID;
- `gamesByArena` — максимум одна активная комната на арену;
- `playerGames` — связь UUID игрока с его комнатой.

Внутренний класс `Game` содержит:

- ведущего и список участников;
- список живых UUID;
- номер раунда и текущую фазу;
- карты и раскрытые категории;
- голоса, использованные пропуски и кандидатов повторного голосования;
- текущего выступающего и состояние его хода;
- задачи лобби, фазы и action bar-таймера.

Фазы перечислены в `Phase`:

```text
LOBBY → STUDY → DISCUSSION → OPEN_DISCUSSION → VOTING → RESOLVING
                                      ↑                  │
                                      └── nextRound() ───┘
```

`FINISHED` устанавливается отдельно при завершении игры. Через короткую задержку комната удаляется из памяти, чтобы участники успели получить финальный отчёт.

### Создание и подключение

Создание проходит через один метод `create()`. Поэтому одинаково проверяются команда, кнопка меню и случайная арена:

1. проверяется `game.creation-enabled`;
2. проверяется корректность настроек;
3. проверяется, что игрок ещё не состоит в комнате;
4. проверяется ID арены;
5. проверяется существование корректной точки `start`;
6. проверяется отсутствие активной комнаты на арене;
7. создаётся лобби и запускается таймер `lobby-seconds`.

ID арены должен содержать от 1 до 32 букв, цифр, `_` или `-`. Арены с некорректными ID пропускаются при загрузке `config.yml`. Это защищает сохранение `games.yml` от неоднозначных YAML-путей.

Подключение проверяет наличие лобби, статус игры, максимальное количество участников и отсутствие другой комнаты у игрока.

### Запуск игры и карты

Ведущий запускает игру только после проверки:

- настройки валидны;
- игра ещё не запущена;
- участников не меньше `min-players`;
- `characteristics.json` успешно загружен.

Каждому участнику выдаётся по одной случайной характеристике из каждой категории. Карты хранятся в памяти комнаты и в `games.yml`; исходные JSON после выдачи не нужны для продолжения уже начатой игры.

Владелец видит полные описания через `/bunker cards`. В общий чат при раскрытии отправляются только категория и название характеристики.

### Очередь личных ходов

В `DISCUSSION` живые игроки идут в порядке списка `alive`. За один ход можно раскрыть только одну ещё не раскрытую категорию. Если игрок не сделал выбор до окончания `speech-seconds`, раскрывается первая доступная категория автоматически.

Сохраняются `current-speaker`, `current-speaker-index` и `current-turn-revealed`. Поэтому после рестарта:

- уже раскрытые карты остаются раскрытыми;
- очередь продолжается с текущего игрока;
- игрок с уже раскрытой картой не получает вторую карту автоматически;
- после завершения текущего хода очередь продолжается дальше.

Если сохранение старого формата не содержит этих полей, игра безопасно начинает обсуждение с первого доступного живого игрока.

### Голосование

В обычном голосовании каждый живой игрок может выбрать номер живого участника или `skip`. Не проголосовавшие учитываются как пропустившие голосование при проверке порога.

Порог равен половине живых игроков с округлением вверх. Если поддержка пропуска достигла порога, а голосов за игроков недостаточно, расходуется один пропуск и начинается следующий раунд.

При ничьей создаётся `runoffVoting` с набором `runoffCandidates`. В повторном голосовании пропуск запрещён. Голосование может повторяться при новой ничьей.

Текущее состояние обычного голосования сохраняется частично: голоса сбрасываются после перезапуска, как и другие временные решения. Режим повторного голосования также не восстанавливается после рестарта и начинается как обычное голосование.

### Выход, отключение и передача ведущего

- выход из лобби удаляет игрока;
- выход ведущего из лобби отменяет комнату;
- `/bunker leave`, разрешённый `/spawn` и отключение после старта считают игрока добровольно выбывшим;
- выбывший удаляется из `alive`, голосов и очереди;
- если выбывает ведущий, ведущим становится первый оставшийся живой игрок по порядку номеров;
- при `alive.size() <= winners-count` игра завершается.

Во время активной игры внешние команды проходят через `PlayerCommandPreprocessEvent`. Разрешены только команды из `allowed-commands`; внутренние `/bunker` остаются доступными. Административные команды настройки и остановки не блокируются для `bunker.admin`.

### Сохранение и восстановление

Состояние хранится в `plugins/Bunker/games.yml`. Записи делаются:

- примерно раз в 30 секунд;
- после важных изменений через отложенное сохранение на 1 тик;
- при выключении сервера.

Перед записью создаётся `games.yml.bak`, а новый файл сначала записывается во временный `games.yml.tmp`. Затем выполняется атомарная замена с запасным неатомарным вариантом.

Сохраняются:

- ведущий, арена, фаза и раунд;
- живые игроки и номера участников;
- карты и раскрытые категории;
- использованные пропуски;
- текущий выступающий и состояние его хода.

При повреждении данных отдельная комната пропускается, а при отсутствии корректного раздела `games` используется резервная копия. Ссылки на раскрытые карты, которых нет в сохранении, очищаются. Меню игроков дополнительно защищено от отсутствующей карты.

После команды `/bunker continue` таймер текущей фазы начинается заново с полным значением из конфига. Это относится к лобби, изучению, личному ходу, общему обсуждению и голосованию.

### Reload

`/bunker reload` перечитывает:

- `config.yml`;
- `messages.yml`;
- `characteristics.json`;
- `catastrophes.json`.

Новые таймеры, лимиты, сообщения и настройки применяются к текущему менеджеру. Уже созданные игры сохраняют собственный объект арены, поэтому изменение координат или `allowed-commands` не переписывает правила старых комнат. Активные таймеры не пересоздаются автоматически.

### Валидация конфигурации

Плагин считает настройки некорректными, если:

- `min-players < 2`;
- `max-players < min-players` или `max-players > 18` (18 — техническая вместимость текущего меню голосования);
- `winners-count < 1` или не меньше `min-players`;
- любой таймер кроме разрешённого нулевого `host-skip-delay-seconds` меньше 1;
- `skip-count < 0`;
- категорий характеристик больше 17.

Некорректная конфигурация не позволяет запускать новые игры. Уже существующие комнаты не удаляются автоматически.

### Сообщения

Игровые сообщения загружаются через `MessageService` и `ConfigManager.message()`. Цвета задаются стандартными кодами `&`, например `&c` или `&6`.

Часто используемые placeholders:

| Placeholder | Значение |
|---|---|
| `%prefix%` | префикс из `messages.yml` |
| `%player%` | имя игрока |
| `%id%` | ID игры или арены |
| `%arena%` | название арены |
| `%number%` | номер участника |
| `%players%` | текущее количество участников |
| `%max_players%` | текущий лимит игроков |
| `%seconds%` | количество секунд |
| `%time%` | время в формате `мм:сс` |
| `%category%` | категория характеристики |
| `%name%` | название характеристики |
| `%reason%` | причина случайного выбывания |

Если сообщение используется в GUI, оно может не содержать `%prefix%`, чтобы префикс не попал в название меню или lore. Сообщения логгера в Java относятся к диагностике сервера и не настраиваются через `messages.yml`.

### Permissions

```yaml
bunker.use:
  default: true

bunker.admin:
  default: op
```

`bunker.use` требуется для команды `/bunker`. `bunker.admin` дополнительно открывает `/bunker reload`, `/bunker setarena`, `/bunker deletearena`, `/bunker delarena` и `/bunker stopall`, а также позволяет не блокировать административные команды во время игры.

Администратор с `bunker.admin` автоматически получает `bunker.use`. Поэтому
команда `/bunker` показывает администратору полный список: сначала команды,
доступные игрокам, затем административные команды. Обычный игрок видит только
свою часть списка.

### Сборка и диагностика

Для сборки используется Java 17 и Paper API 1.20.4 как compile-only dependency:

```bash
gradle build
```

JAR создаётся в `build/libs/Bunker-0.1.0.jar`. Перед установкой рекомендуется проверить `git diff --check` и YAML-файлы.

Если Gradle сообщает об ошибке `libnative-platform.dylib`, это проблема локальной установки Gradle/нативной библиотеки, а не диагностированная ошибка Java-кода. В таком случае сборку нужно повторить в рабочем окружении Gradle.

Не удаляйте `plugins/Bunker/games.yml` и `games.yml.bak`, если хотите продолжить незавершённые игры.

Исходные JSON находятся в:

```text
src/main/resources/characteristics.json
src/main/resources/catastrophes.json
```

Рабочие копии сервера находятся в:

```text
server/plugins/Bunker/characteristics.json
server/plugins/Bunker/catastrophes.json
```

Сервер читает рабочие копии. После их изменения перезапустите сервер.

Сейчас доступно:

- 55 вариантов в каждой категории;
- 385 характеристик всего;
- 10 катастроф.

Категории:

`Возраст`, `Здоровье`, `Профессия`, `Хобби`, `Багаж`, `Фобия`, `Секрет`.

Формат элемента характеристики:

```json
{
  "name": "Врач",
  "description": "Лечит людей и организует медицинский блок."
}
```

Если JSON повреждён, плагин сохраняет его копию рядом:

```text
characteristics.json.broken-<timestamp>
```

При повреждённом файле характеристик игра не запускается. При повреждённом файле катастроф используется запасное описание.

## Установка

### Совместимость клиентов разных версий

В локальный сервер уже добавлены:

- `ViaVersion-5.12.0.jar` — подключение клиентов новее версии Paper;
- `ViaBackwards-5.12.0.jar` — подключение клиентов старше версии Paper.

`ViaBackwards` требует `ViaVersion`. После добавления или обновления этих плагинов нужен полный перезапуск Paper, а не `/reload`.

Bunker не использует NMS и не зависит от API ViaVersion, поэтому его JAR не нужно пересобирать под каждую версию клиента. Серверную версию Paper следует держать стабильной, а преобразование протоколов оставлять ViaVersion/ViaBackwards.

Важно: ViaVersion не добавляет старому клиенту новые блоки, предметы и механики. Для версий 1.8 и ниже дополнительно потребуется ViaRewind. Проверить версию подключившегося игрока можно командой `/viaversion list`.

1. Соберите проект или возьмите `Bunker-0.1.0.jar`.
2. Скопируйте JAR в `server/plugins/`.
3. Полностью перезапустите сервер.
4. Убедитесь, что в консоли появилось `Bunker включён!`.
5. Создайте комнату командой `/bunker create`.

После замены JAR сервер нужно перезапустить. Не заменяйте файл плагина во время работы сервера.
