BUNKER — ПОЛНЫЙ ОДНОПРОХОДНЫЙ ЧЕК-ЛИСТ ПРОВЕРКИ
================================================

Цель
----
Проверить плагин на чистом сервере Paper одним последовательным прогоном:
команды, permissions, арены, лобби, карты, ходы, голосования, выход игроков,
reload, сохранение, рестарт и повреждённое сохранение.

Подготовка
----------
[ ] Запустить Paper-сервер с Java 17.
[ ] Установить собранный Bunker-0.1.0.jar в plugins/.
[ ] Убедиться, что в мире существует мир из arenas.<id>.start.world.
[ ] Выдать тестовым игрокам permission bunker.use.
[ ] Выдать одному тестовому игроку bunker.admin или сделать его OP.
[ ] Подключить 12 тестовых игроков, если нужно проверить максимальный лимит.
[ ] Перед первым запуском сохранить копию plugins/Bunker/./op

1. Файлы и запуск
-----------------
[ ] Запустить сервер.
[ ] Проверить, что появились config.yml, messages.yml,
    characteristics.json и catastrophes.json.
[ ] Проверить отсутствие SEVERE об ошибках JSON/config.
[ ] Проверить, что плагин пишет сообщение о включении.
[ ] Выполнить /bunker help.
[ ] Выполнить /bunker rules и проверить полный справочник новичка.
[ ] Изменить одну строку rules в messages.yml, выполнить reload и проверить новый текст.
[ ] Убедиться, что обычный игрок видит игровые команды.
[ ] Убедиться, что консоль получает сообщение players-only для игровых команд.

2. Permissions и администрирование
-----------------------------------
[ ] Игрок без bunker.use не может выполнить /bunker.
[ ] Игрок с bunker.use может выполнить /bunker status и /bunker games.
[ ] Игрок без bunker.admin получает отказ на /bunker reload.
[ ] Администратор выполняет /bunker reload и получает успешное сообщение.
[ ] Администратор выполняет /bunker setarena <id> start.
[ ] Проверить, что координаты и направление записались в config.yml.
[ ] Проверить /bunker deletearena <id> на свободной арене.
[ ] Создать арену заново через setarena для дальнейшего теста.

3. Проверка ID арен
-------------------
Проверить, что setarena/create/delete отклоняют:
[ ] пустой ID;
[ ] ID с пробелом;
[ ] ID с точкой;
[ ] ID со слэшем;
[ ] ID с двоеточием;
[ ] ID длиннее 32 символов.
[ ] Проверить, что ID с буквами, цифрами, _ и - принимается.
[ ] Добавить в config.yml арену с некорректным ID и выполнить reload.
[ ] Убедиться, что некорректная арена пропущена и сервер не падает.

4. Создание и лобби
-------------------
[ ] Установить game.creation-enabled: true.
[ ] Выполнить /bunker create без ID и проверить меню выбора арены.
[ ] Проверить свободную арену: она подписана как доступная для создания.
[ ] Создать игру через /bunker create <id>.
[ ] Убедиться, что создатель стал ведущим и участником №1.
[ ] Проверить сообщение с ID арены и командой подключения.
[ ] Проверить action bar с lobby-seconds в формате мм:сс.
[ ] Второй игрок выполняет /bunker join <id>.
[ ] Проверить сообщение о присоединении и количество игроков.
[ ] Проверить /bunker join random.
[ ] Проверить, что переполненное лобби не выбирается random.
[ ] Открыть меню создания ещё раз.
[ ] Убедиться, что занятая арена явно показывает «Занято» и не предлагает создать игру.
[ ] Нажатие на занятую арену должно показать сообщение busy.
[ ] Установить game.creation-enabled: false и выполнить /bunker reload.
[ ] Проверить отказ на /bunker create и отказ при нажатии старой кнопки меню.
[ ] Вернуть game.creation-enabled: true и выполнить reload.

5. Старт и изучение карт
------------------------
[ ] Проверить отказ ведущему при количестве игроков меньше min-players.
[ ] Набрать минимум 6 игроков.
[ ] Обычный участник выполняет /bunker start и получает отказ.
[ ] Ведущий выполняет /bunker start.
[ ] Проверить телепортацию участников на start со случайным смещением.
[ ] Проверить начало STUDY, катастрофу и action bar.
[ ] Выполнить /bunker cards у каждого участника.
[ ] Убедиться, что каждый видит только свои полные карты.
[ ] Проверить, что администратор/другой игрок не может посмотреть чужие карты.
[ ] Проверить досрочное завершение STUDY до host-skip-delay-seconds.
[ ] Убедиться, что ведущий получает отказ до истечения задержки.
[ ] После задержки ведущий выполняет /bunker pass.

6. Личные ходы
--------------
[ ] Проверить, что игроки получают ход строго по номерам.
[ ] Текущий игрок открывает меню через /bunker open.
[ ] Другой игрок не может выбрать характеристику текущего игрока.
[ ] Текущий игрок раскрывает одну карту.
[ ] Проверить сообщение в общем чате: категория и название без описания.
[ ] Проверить, что повторное открытие второй карты в том же ходу невозможно.
[ ] Текущий игрок выполняет /bunker pass.
[ ] Проверить переход к следующему игроку.
[ ] Одному игроку не делать выбор до окончания speech-seconds.
[ ] Проверить автоматическое раскрытие первой доступной карты.
[ ] Проверить, что после раскрытия всех карт игрок пропускается корректно.

7. Обсуждение и голосование
---------------------------
[ ] Дождаться OPEN_DISCUSSION или завершить её ведущим после задержки.
[ ] Проверить action bar общего обсуждения.
[ ] Обычный игрок не может завершить обсуждение через /bunker pass.
[ ] Выполнить /bunker open и открыть меню голосования.
[ ] Проверить голос за живого игрока через меню.
[ ] Проверить голос через /bunker vote <номер>.
[ ] Проверить /bunker vote skip.
[ ] Проверить отказ повторного skip после исчерпания skip-count.
[ ] Проверить досрочное разрешение после голосов всех живых.
[ ] Проверить авторазрешение по окончании voting-seconds.
[ ] Проверить порог: skip и неголосовавшие учитываются как пропуск.
[ ] Создать ничью и проверить запуск повторного голосования.
[ ] Убедиться, что в повторном голосовании skip недоступен.
[ ] Создать повторную ничью и проверить новый runoff.
[ ] Проверить случайное выбывание при отсутствии голосов после исчерпания пропусков.

8. Выход и ведущий
------------------
[ ] Игрок выполняет /bunker leave в лобби.
[ ] Проверить сообщение остальным игрокам и освобождение его номера.
[ ] Ведущий выполняет /bunker leave в лобби.
[ ] Проверить отмену всей комнаты.
[ ] Живой игрок выполняет /bunker leave во время игры.
[ ] Проверить сообщение «добровольно покинул бункер».
[ ] Живой игрок выполняет разрешённый /spawn.
[ ] Проверить добровольное выбытие и недоступность голоса/хода.
[ ] Проверить отключение живого игрока от сервера.
[ ] Проверить передачу ведущего следующему живому игроку.
[ ] Проверить завершение игры при двух или одном живом игроке.

9. Ограничение внешних команд
-----------------------------
[ ] Во время активной игры выполнить запрещённую внешнюю команду.
[ ] Убедиться, что команда отменена и показан список разрешённых команд.
[ ] Проверить разрешённый /spawn.
[ ] Проверить, что внутренние /bunker status, cards, open и pass работают.
[ ] Проверить административные setarena/stopall/deletearena у администратора.
[ ] Проверить, что обычный игрок не получает обход блокировки.

10. Перезапуск и продолжение
----------------------------
[ ] Создать новую комнату и выключить сервер в лобби.
[ ] Запустить сервер и проверить восстановление лобби и таймера.
[ ] Запустить игру и перезапустить сервер во время STUDY.
[ ] Проверить восстановление карт и полный таймер текущего этапа.
[ ] Перезапустить сервер во время DISCUSSION до раскрытия карты.
[ ] Проверить, что очередь продолжается с текущего игрока.
[ ] Раскрыть карту, но не завершать ход, перезапустить сервер.
[ ] Проверить, что карта осталась раскрытой и вторая карта не предлагается.
[ ] Завершить ход через /bunker pass и проверить переход очереди.
[ ] Перезапустить сервер во время OPEN_DISCUSSION и VOTING.
[ ] Проверить, что голоса сброшены после рестарта.
[ ] Отдельно проверить, что повторное голосование после рестарта становится обычным.

11. reload и сообщения
----------------------
[ ] Изменить lobby-seconds, выполнить reload и создать новую игру.
[ ] Проверить, что сообщение автоотмены показывает новое мм:сс.
[ ] Изменить текст и цвет сообщения в messages.yml, выполнить reload.
[ ] Проверить новый текст в чате, GUI и action bar.
[ ] Изменить allowed-commands арены и проверить поведение новой игры.
[ ] Убедиться, что старые игры не получили новые настройки арены.

12. Повреждённые данные
-----------------------
[ ] Сделать резервную копию games.yml и games.yml.bak.
[ ] Внести в games.yml несуществующую раскрытую категорию.
[ ] Запустить сервер.
[ ] Проверить, что игра восстанавливается без падения.
[ ] Открыть /bunker players.
[ ] Проверить, что меню не падает и отсутствующая карта отображается безопасно.
[ ] Проверить повреждённый UUID/раздел отдельной игры.
[ ] Убедиться, что повреждённая комната пропущена, а остальные комнаты загружаются.
[ ] Восстановить резервные файлы после теста.

13. Завершение прогона
----------------------
[ ] Проверить отсутствие новых SEVERE и stacktrace в логе.
[ ] Выполнить /bunker stopall.
[ ] Убедиться, что активных комнат больше нет.
[ ] Корректно остановить сервер.
[ ] Проверить финальные games.yml и games.yml.bak.
[ ] Сохранить лог и отметить все незакрытые пункты.

Результат
---------
Прогон считается успешным, если все пункты отмечены, сервер не падает,
игра проходит от создания до финала, состояние восстанавливается после
перезапуска, а пользовательские сообщения и значения таймеров соответствуют
config.yml и messages.yml.
